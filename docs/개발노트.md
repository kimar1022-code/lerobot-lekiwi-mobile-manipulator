# 개발 노트 (LeKiwi Bringup)

초기 세팅 세션의 진행 내역과, README에 다 넣지 않은 디버깅 기록.

## 진행 순서

1. 네트워크 - 라즈베리파이 고정 IP (nmcli manual). LeKiwi Pi5는 `192.168.75.20`.
2. 팔로워 모터 ID 등록 (9축) → 스캔 검증.
3. 팔로워 캘리브레이션 (호밍 → 팔 범위 기록 → 그리퍼 모터측정 → 병합/저장 → 정규화 검증).
4. 데스크탑↔Pi 연결 확인, 옴니휠 6방향 주행 테스트.
5. 리더팔 세팅 (드라이버 보드 교체 → ID 등록 6축 → 캘리브레이션).
6. 팔 미러링 조종 테스트 (배터리 방전으로 전체 조종은 다음으로).

## 캘리브레이션 메모

- 팔로워 캘리는 lerobot 표준 흐름(`set_half_turn_homings` → `record_ranges_of_motion`)을 단계별 스크립트로 분리. 대화형 `lerobot-calibrate`가 헤드리스 환경에서 입력을 못 받아 그대로 못 돌렸기 때문.
- `record_arm.py`에 이상값 필터(직전값 대비 급점프 무시)를 넣음 - 긴 기록 중 통신이 한 번 튀면 극단값(0/4095)이 min/max에 박혀버리는 문제 방지.
- 무한회전 축(wrist_roll, 바퀴 3축)은 범위를 0~4095 고정.
- 캘리 값은 참고용 SO-101 값과 관절 가동폭이 유사한지로 sanity check. 팔 관절 폭 ~2200–2900, 그리퍼 ~1500이 정상 범위.

## 디버깅 기록 (README 외)

### 케이블/커넥터
- USB 시리얼 어댑터가 인식 안 될 때, 상당수는 **충전 전용 USB 케이블**(데이터선 없음)이 원인. 데이터 케이블로 교체하면 잡힘. (Pi 보드, 데스크탑 리더 보드 모두 한 번씩 겪음)
- 3핀 서보 케이블은 양 끝(보드 서보포트 ↔ 모터)이 다 물려야 함. 한쪽만 꽂혀 대롱거리면 무응답.

### 드라이버 보드 (Waveshare Bus Servo Adapter A)
- 점퍼: **A = UART 제어, B = USB 제어**. PC/라즈베리파이4B 등 USB로 제어할 땐 **B**.
- 전원(초록 DC단자, 9~12.6V)과 USB 통신칩 전원은 별개. USB만 꽂으면 통신칩만 켜지고 서보는 안 움직임. 서보용 DC 전원 필수.
- 위 항목을 다 확인해도 무응답이면 보드 자체 불량을 의심. 핑 응답이 계속 -6(무응답)이고 -7(충돌)조차 안 나오면 신호가 서보까지 안 가는 것. 실제로 리더 보드 교체 후 즉시 정상화.

### 모터 ID 등록
- 새 모터는 전부 ID 1 → 여럿 물리면 ID 1 핑에 충돌(-7). 한 축씩만 연결해 등록.
- 데이지체인에서는 "끝에서부터 하나씩 늘려가기"가 편함: 이미 새긴 축은 고유 ID라 안 걸리고, 새로 이은 축만 ID 1이라 그것만 잡힘.
- 주의: 등록하려는 축이 실제로 ID 1로 버스에 올라왔는지 매번 스캔 확인. 안 그러면 직전에 등록한 축(고유 ID)을 도구가 붙잡아 덮어씀. (옴니휠 등록 중 오른쪽 바퀴가 9→8→7로 덮어써진 사고 있었음 → 하나씩 다시 연결해 교정)

### 호스트 데몬 운영
- `lekiwi_host`는 기본 `connection_time_s=30`초 뒤 자동 종료. 길게 쓰려면 `--host.connection_time_s` 크게.
- SSH로 백그라운드 실행 시 세션이 끊기면 SIGHUP으로 같이 죽음. `setsid nohup ... </dev/null &`로 분리 실행해야 유지됨.
- 명령이 안 오면 워치독이 베이스를 멈춤("Stopping the base") - 정상 동작.

### 조종 API
- 클라이언트 `send_action`은 보낸 키만 전송. 하지만 팔로워 `send_action`은 옴니휠 역기구학 때문에 x/y/theta.vel 3키를 항상 요구 → 바퀴만 테스트할 때도 3키를 0으로라도 넣어야 함. 반대로 팔만 보낼 땐 arm.pos + 바퀴 0으로.
- 팔 미러링 시작 시 팔로워가 리더 자세로 튀는 걸 막으려 2.5초 램프(현재자세→리더자세 보간) 적용.

### 배터리
- 3S 리튬이온: 만충 12.6V, 방전 근처 ~9.9V. 10.5V면 부하 시 sag로 모터가 간헐 드롭될 수 있음.
- 응답하는 모터의 Present_Voltage(주소 62, 0.1V 단위)로 버스 전압을 읽어 진단 가능(`read_batt.py`).

## 2026-10-05 - 자율 집기

### 하드웨어 점검
- 리더팔 6축 전부 무응답. USB 칩은 인식되고 통신속도 5종 × ID 0~253 전수 스캔에도 응답 0. USB 만 꽂으면 LED 가 켜지고 12V 어댑터만 꽂으면 안 켜짐 → 보드 전원 입구 고장. 원인은 전날 컨베이어용 24V 어댑터를 잘못 연결한 것(보드 최대 12.6V).
- 교체 보드(다른 SO-ARM 에서 가져옴)는 점퍼가 A 여서 B 로 바꾼 뒤 6/6 응답, 12.2~12.4V, 27~29°C.
- 모터 손상 여부: Status 레지스터(65) 6축 모두 0, 손 스윕으로 범위 · 튐 · 읽기실패 확인. 손목회전만 손으로 돌려도 값이 2046~2052 에 머물러 의심했으나, 토크 30% 로 ±300 구동하니 2047→2344→1906→2046 으로 정상 추종 → 센서 정상(손 시험에서 다른 관절을 돌린 것으로 판단).
- 모터 배터리가 충전기 연결 중에도 12.3→11.7V 로 하락. 출력을 끊고 20분 충전해도 그대로라 "출력 중 충전 불가" 가설 배제 → 충전기가 배터리가 아니라 모터 드라이버에 꽂혀 있었음. 배터리에 꽂자 1분에 11.7→11.9V.

### 호스트 자동 재시작
